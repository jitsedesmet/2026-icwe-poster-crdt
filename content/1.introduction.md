## Introduction
{:#introduction}

The paradigm of neuro-symbolic AI aims to improve the accuracy, trustworthiness, and explainability of AI agents by grounding their reasoning in structured symbolic knowledge.
[Knowledge graphs expressed in RDF](cite:cites spec:rdf) have become a central pillar of this approach:
techniques such as [GraphRAG](cite:cites graphrag) augment LLM answers with retrieved graph structures,
zero-shot SPARQL generation with [GRASP](cite:cites grasp) allows agents to query arbitrary knowledge graphs without fine-tuning,
and the recently introduced [Model Context Protocol (MCP)](cite:cites mcp) connects LLM agents to live knowledge bases, including knowledge graphs through, e.g., SPARQL-based tools, without pre-computation.
These developments make it increasingly common for multiple agents to read from and write to the same RDF knowledge graph simultaneously:
one agent enriches the graph while another reasons over it, and a third corrects errors it discovers.

At the same time, decentralized data ecosystems-systems such as
[Solid](cite:cites solid), [IDSA](cite:cites idsa), or [Gaia-X](cite:cites gaia-x),
in which each participant governs their own data without relying on a central authority, gain popularity.
A critical challenge in these ecosystems is concurrent offline editing of shared data.
When two agents independently modify the same resource without coordination,
their updates collide.
Any offline-first system requires a system to recover from such collisions,
be it dropping the update, prompting the user, or resolving it using some algorithm. 

In the age of agentic systems,
prompting the agent to recover might be possible,
but not necessarily desired.
An agent that has been offline for some period of time might have difficulty grasping how long it has been offline and how the data has changed in that time.
To this end, the evolution of the data should be tracked, at which point we fall back to traditional approaches.
[Conflict-free Replicated Data Types (CRDTs)](cite:cites CRDTs) have been around for a long time,
as they guarantee that any two replicas converge to the same state through specified algorithms.

Even though solutions have been proposed for [RDF based CRDTs](cite:cites rdf-crdt),
and even [CRDTs in Solid](cite:cites solid-crdt-yjs),
the introduction of [RDF 1.2](cite:cites rdf-1-2)
changes the landscape as it enables efficient modelling of state based CRDTs.

In this paper we present a state-based add-wins set CRDT modeled entirely in RDF 1.2.
keeping the data's bookkeeping within the same dataset, removing the need for separate bookkeeping,
while still allowing both CRDT aware and CRDT-unaware clients to live harmoniously.
Using RDF 1.2 allows for CRDT abstraction at the quad-store level, streamlining integration within query engines,
as proven by our PoC implementation using [Comunica](cite:cites comunica).
